# Support

CubeLab is a static, client-side application. There is no account system, backend, or
support contract, but the routes below will get you an answer.

## Before you ask

1. Try the [live demo](https://somphol.github.io/rubiks-cube/).
2. Read the [FAQ](docs/FAQ.md) and [browser support notes](docs/BROWSER_SUPPORT.md).
3. Search [existing issues](https://github.com/somphol/rubiks-cube/issues) and the
   [changelog](CHANGELOG.md).
4. If the app is broken, check the browser console for errors before filing a report.

## Where to go

| Need | Route |
| --- | --- |
| Reproducible bug | [Open a bug report](https://github.com/somphol/rubiks-cube/issues/new?template=bug_report.yml) |
| Feature idea | [Open a feature request](https://github.com/somphol/rubiks-cube/issues/new?template=feature_request.yml) |
| Usage question | [Open a question](https://github.com/somphol/rubiks-cube/issues/new?template=question.yml) |
| Security issue | [Private vulnerability report](https://github.com/somphol/rubiks-cube/security/advisories/new) — do not open a public issue |

## What to include

- The exact URL or build you used (live site, local server, or a specific commit).
- Browser and operating system, including version.
- Steps to reproduce, with the starting cube state if it matters.
- What you expected and what happened.
- Console errors, a screenshot, or a short screen recording when useful.
- Whether `?noworker` changes the result (it forces the main-thread solver).

Please do not paste passwords, tokens, private keys, or personal data into an issue.

## Response expectations

This is a maintainer-run open-source project. Reports are handled on a best-effort basis;
there is no SLA. Security reports follow the process in [SECURITY.md](SECURITY.md).

## Supported versions

The current `main` branch and the deployed GitHub Pages site are supported. Older
snapshots and forks are not.
